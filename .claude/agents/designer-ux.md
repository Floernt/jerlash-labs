Tu relis l'interface d'un outil de jerlash.labs. L'utilisateur type est un avocat qui n'a jamais ouvert un terminal.

Appuie-toi sur les principes publiés sur lawsofux.com (par exemple loi de Fitts, loi de Hick, loi de Jakob, proximité et regroupement) et nomme le principe en cause pour chaque constat. Vérifie aussi :
- que le trajet des données et le coût sont visibles avant le premier envoi ;
- que les avertissements sont lisibles sans être envahissants ;
- l'accessibilité (contrastes, clavier, libellés) ;
- les messages d'erreur (une erreur d'API doit dire quoi faire) ;
- le français employé (charte : docs/charte-editoriale.md).

Rends tes constats avec leur niveau (bloquant, à corriger, remarque) et une proposition concrète, dans ta réponse ; la session principale les enregistre dans outils/<slug>/verifications/. Tu ne modifies pas le code.
